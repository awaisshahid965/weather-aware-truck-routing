# Plan 03: Frontend scaffold (Next.js)

## Goal

Create `frontend/`: a Next.js app that is ready for features, but has none yet.

When this plan is done:

- The app runs locally and shows a placeholder home page.
- The folder structure for routes, context, and shared code is in place.
- Public configuration is read in one place and checked at startup.
- Formatting, linting, strict type checks, and component tests all pass with one command.
- A production image builds from the standalone output and runs as a non-root user.
- CI runs every check, builds the app, audits production dependencies, and smoke-tests the image.

## Scope

**In scope:** project files, dependencies, TypeScript, ESLint, Prettier, Tailwind, Vitest, folder skeleton, public config, Docker image, CI workflow, frontend docs.

**Out of scope (built with features later):**

- Pages beyond the placeholder home page.
- API types, the HTTP client, and services.
- Context providers and state.
- UI components, the map, and the heatmap.

### 4. Next.js configuration

- `cacheComponents` and `partialPrefetching` are the defaults that create-next-app 16.4.1 turns on. They are kept.
- `output: 'standalone'` produces a self-contained server for the container.
- The repository root has its own `package-lock.json` (for git hook tools). Without a pinned root, Next.js treats the whole repository as a workspace. It warns and nests the standalone output under `frontend/`. Pinning both roots to this folder prevents that.
- React Compiler stays off (the create-next-app default). Turn it on later only if profiling shows re-render costs.

**`frontend/next.config.ts`**

```ts
import type { NextConfig } from 'next'

// The repository root has its own package-lock.json (git hook tooling). Pin the app root so Next.js does not
// mistake the repository for a workspace and nest the standalone output under `frontend/`.
const APP_ROOT = __dirname

const nextConfig: NextConfig = {
    cacheComponents: true,
    partialPrefetching: true,
    // Self-contained server bundle for the production container (see Dockerfile).
    output: 'standalone',
    outputFileTracingRoot: APP_ROOT,
    poweredByHeader: false,
    turbopack: {
        root: APP_ROOT,
        rules: {
            '*.css': {
                loaders: ['@tailwindcss/turbopack'],
                as: '*.css',
            },
        },
    },
}

export default nextConfig
```

Lint rules on top of Next's recommended sets:

| Rule | Why |
|---|---|
| `camelcase` | One naming style for identifiers |
| `eqeqeq` | No type-coercing `==` |
| `require-await` | An `async` function without `await` is usually a bug |
| `no-console` (except `warn`, `error`) | No stray debug output |
| `@typescript-eslint/consistent-type-imports` | Type-only imports are erased at build time and stay visible as such |

`eslint-config-prettier` comes last. It turns off every rule that would fight Prettier.

```js
    ...nextTs,

            camelcase: 'error',
```

The one module that reads `process.env`. Next.js inlines `NEXT_PUBLIC_*` values only where they are written out in full, so each variable is read by its full name.

**`frontend/src/shared/config/app-config.ts`**

```ts
/**
 * Public runtime configuration, read in one place.
 *
 * Next.js inlines `NEXT_PUBLIC_*` variables into the bundle at build time, and only where they are referenced
 * literally, so each variable is read by its full name below. A missing value fails the build or the first import
 * instead of producing requests to `undefined`.
 */
const readRequired = (name: string, value: string | undefined): string => {
    if (!value) {
        throw new Error(`${name} is not set. Copy .env.example to .env.local and fill it in.`)
    }
    return value
}

export const API_BASE_URL = readRequired('NEXT_PUBLIC_API_BASE_URL', process.env.NEXT_PUBLIC_API_BASE_URL)

export const MAP_STYLE_URL = readRequired('NEXT_PUBLIC_MAP_STYLE_URL', process.env.NEXT_PUBLIC_MAP_STYLE_URL)
```

### 8. Tests

- Vitest runs in jsdom, with the React plugin.
- The `@/*` alias comes from `tsconfig.json`, so it is defined only once.
- Test runs get fixed public variables. A developer's `.env.local` never changes test results.
- Mocks and stubbed variables reset after every test.

**`frontend/vitest.config.mts`**

```ts

export default defineConfig({
    plugins: [react()],
    resolve: {
        // Reuse the `@/*` alias from tsconfig.json.

    test: {
        environment: 'jsdom',
        include: ['src/**/*.test.{ts,tsx}'],
```

### 10. Production image

Three stages:

1. **deps:** `npm ci` installs exactly what the lockfile records.
2. **build:** `next build` creates the standalone server. `NEXT_PUBLIC_*` values are build arguments, because Next.js inlines them at this step.
3. **runtime:** only the standalone output, run as the unprivileged `node` user.

**`frontend/Dockerfile`**

```dockerfile
# syntax=docker/dockerfile:1

# --- Dependencies: install exactly what the lockfile records -------------------------
FROM node:24.22.0-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json .npmrc ./
RUN --mount=type=cache,target=/root/.npm npm ci

# --- Build: compile the standalone server. NEXT_PUBLIC_* values are inlined here. --------
FROM node:24.22.0-alpine AS build
WORKDIR /app
ARG NEXT_PUBLIC_API_BASE_URL
ARG NEXT_PUBLIC_MAP_STYLE_URL
ENV NEXT_PUBLIC_API_BASE_URL=$NEXT_PUBLIC_API_BASE_URL \
    NEXT_PUBLIC_MAP_STYLE_URL=$NEXT_PUBLIC_MAP_STYLE_URL \
    NEXT_TELEMETRY_DISABLED=1
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

# --- Runtime: only the standalone output, as the unprivileged `node` user ----------------
FROM node:24.22.0-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production \
    NEXT_TELEMETRY_DISABLED=1 \
    HOSTNAME=0.0.0.0 \
    PORT=3000
COPY --from=build --chown=node:node /app/public ./public
COPY --from=build --chown=node:node /app/.next/standalone ./
COPY --from=build --chown=node:node /app/.next/static ./.next/static
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD ["sh", "-c", "wget -q --spider http://127.0.0.1:${PORT}/ || exit 1"]
CMD ["node", "server.js"]
```

**`frontend/CONVENTIONS.md`**

````markdown
# Frontend conventions

Rules for code in `frontend/`. Tools enforce most of them. Reviews enforce the rest.

## Structure

```text
src/
├── app/                        Routes only. Thin: compose shared components.
├── context/<name>/             Shared state, one folder per context
│   ├── <name>.interface.ts     The <Name>ContextValue interface
│   ├── <name>.context.ts       createContext + use<Name>Context hook
│   └── <name>.container.tsx    Owns the state, calls services, renders the provider
└── shared/
    ├── components/<name>/      Composed, product-aware components
    ├── ui/<name>/              Generic controls with no product knowledge (button, input, select)
    ├── services/               API access: http-client.ts + one service per resource
    ├── types/                  Shared types and API data shapes
    ├── utils/                  Pure helpers
    └── config/                 app-config.ts: the only reader of process.env
tests/                          Shared test setup, fixtures, factories
```

## Component folders

One component per folder, named after the component. Its files sit together:

| File | Holds |
|---|---|
| `route-card.tsx` | The component (default export) |
| `route-card.types.ts` | Props interface and closed sets |
| `route-card.styles.ts` | Tailwind class maps for variants |
| `route-card.utils.ts` | Pure helpers used only here |
| `route-card.test.tsx` | Tests |
| `hooks/use-route-card.ts` | The component's own logic, as a hook (default export) |
| `route-card-header/` | A sub-component, in its own folder |

## Naming

| Thing | Style | Example |
|---|---|---|
| File, folder | `kebab-case` | `route-card.tsx`, `use-trip-planner.ts` |
| Component | `PascalCase` | `RouteCard` |
| Hook | `use` + `PascalCase` | `useTripPlanner` |
| Function, variable | `camelCase` | `formatEta` |
| Constant | `UPPER_SNAKE_CASE` | `API_BASE_URL` |
| Type, interface | `PascalCase`, no `I` prefix | `RoutePlan` |
| Props | `<Component>Props` | `RouteCardProps` |
| Context value | `<Name>ContextValue` | `TripContextValue` |
| Service class | `<Resource>Service` | `TripService` |

## Components

- Write components as typed arrow functions, then export them as the default:

  ```tsx
  const RouteCard: FC<RouteCardProps> = ({ route }) => {
      return <article>{route.label}</article>
  }

  export default RouteCard
  ```

- Route files in `app/` use `export default function Page()`, as Next.js expects.
- Components are Server Components by default. Add `'use client'` only to the component that needs state, effects, or browser APIs, as deep in the tree as possible. Never add it to `layout.tsx`.
- Components that use browser-only libraries, such as MapLibre, load on the client only.
- Keep components mostly markup. Move logic into `hooks/use-<name>.ts`.

## Exports and imports

- Default export: components, hooks, service classes.
- Named exports: types, constants, context objects with their `use<Name>Context` hooks, utilities.
- Use `@/` for anything outside the current component folder: `import TripService from '@/shared/services/trip-service'`.
- Use relative imports only inside the same component folder: `import { routeCardClasses } from './route-card.styles'`.
- Use `import type` for type-only imports. ESLint enforces it.

## Types

- `interface` for object shapes. `type` for unions and aliases.
- Closed sets are string-literal unions. When the values are needed at runtime, derive the type from an `as const` array:

  ```ts
  export const BUTTON_VARIANTS = ['primary', 'secondary'] as const
  export type ButtonVariant = (typeof BUTTON_VARIANTS)[number]
  ```

- No TypeScript `enum`. Unions are erased at build time and match the strings the API sends.
- No `any`. Use `unknown` and narrow it.
- TypeScript is strict, plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.

## State

- Keep state local until two distant components need it. Then lift it into a context.
- A context lives in `context/<name>/`, split into three files:
  - `<name>.interface.ts`: the `<Name>ContextValue` interface.
  - `<name>.context.ts`: `createContext<<Name>ContextValue | null>(null)`, plus a `use<Name>Context()` hook. The hook throws a clear error when used outside the provider.
  - `<name>.container.tsx`: a client component that owns the state, calls services, and renders the provider.

## Services and data

- Components never call `fetch`. Services do.
- `shared/services/http-client.ts` is a base class with protected static request helpers. Each resource gets a service class that extends it, with static methods: `TripService.createPlan(request)`.
- Each service keeps its endpoint paths in one constant object.
- Services turn API responses into the app's types and throw typed errors. Components never parse raw JSON.
- Configuration comes from `shared/config/app-config.ts` only.

## Styling

- Use Tailwind utility classes in JSX.
- Variants live in `<name>.styles.ts`, as maps keyed by a union type:

  ```ts
  export const buttonVariantClasses: Record<ButtonVariant, string> = {
      primary: 'bg-sky-600 text-white hover:bg-sky-700',
      secondary: 'bg-neutral-200 text-neutral-900 hover:bg-neutral-300',
  }
  ```

- Never build class names from fragments such as `` `bg-${color}-500` ``. Tailwind ships only classes it finds written out in full.
- Use rem-based sizes. Keep the browser's default root font size, so user font settings still work.

## Errors

- Show the user what went wrong and what to do next. Never swallow an error silently.
- Use only `console.warn` and `console.error`. ESLint blocks `console.log`.

## Tests

- Vitest, React Testing Library, and user-event. Test files sit next to the code: `route-card.test.tsx`.
- Query the way a user would: by role, label, or text. Use test IDs only when nothing else works.
- Tests never touch the network. Mock the service, not `fetch`.
- `tests/` holds shared setup, fixtures, and factories.

## Comments

Explain why, never what. No commented-out code.

## Formatting

Prettier formats all code and config: 4-space indents (2 for JSON and YAML), single quotes, no semicolons, trailing commas, 120 columns, LF. Markdown is left as written. Run `npm run format`. ESLint covers correctness: `npm run lint:fix`.
````

### 12. CI workflow and Dependabot

The workflow has two jobs:

1. **checks:** install from the lockfile, run every check, build, and audit production dependencies.
2. **image:** build the Docker image with the public build arguments, start it, and wait for the home page.

Actions are pinned to full commit SHAs, with the version in a comment. Dependabot keeps them current.

**`.github/workflows/frontend.yml`**

```yaml
name: Frontend

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

defaults:
  run:
    working-directory: frontend

env:
  NEXT_TELEMETRY_DISABLED: '1'
  NEXT_PUBLIC_API_BASE_URL: https://api.example.com/api/v1
  NEXT_PUBLIC_MAP_STYLE_URL: https://tiles.openfreemap.org/styles/liberty

jobs:
  checks:
    name: Format, lint, type-check, test, build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version-file: frontend/.nvmrc
          cache: npm
          cache-dependency-path: frontend/package-lock.json
      - name: Install dependencies
        run: npm ci
      - name: Check formatting
        run: npm run format:check
      - name: Lint
        run: npm run lint
      - name: Type-check
        run: npm run typecheck
      - name: Test
        run: npm run test
      - name: Build
        run: npm run build
      - name: Audit production dependencies
        run: npm audit --omit=dev --audit-level=high

  image:
    name: Build and smoke-test the image
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: docker/setup-buildx-action@f87e5991a6d7451dcb8d9637bfbc97413f497069 # v4.4.1
      - uses: docker/build-push-action@c3c9e263c25d99ce0380d002d59b67737d91b0dc # v7.4.0
        with:
          context: frontend
          load: true
          tags: truck-routing-frontend:ci
          build-args: |
            NEXT_PUBLIC_API_BASE_URL=${{ env.NEXT_PUBLIC_API_BASE_URL }}
            NEXT_PUBLIC_MAP_STYLE_URL=${{ env.NEXT_PUBLIC_MAP_STYLE_URL }}
          cache-from: type=gha,scope=frontend
          cache-to: type=gha,mode=max,scope=frontend
      - name: Start the container and wait for the home page
        run: |
          docker run --detach --name frontend --publish 3000:3000 truck-routing-frontend:ci
          for _ in $(seq 1 30); do
            if curl --fail --silent --output /dev/null http://localhost:3000/; then exit 0; fi
            sleep 1
          done
          docker logs frontend
          exit 1
```
