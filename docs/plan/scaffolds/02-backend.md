# Plan 02: Backend scaffold (Django)

## Goal

Create `backend/`: a Django REST API that is ready for features, but has none yet.

When this plan is done:

- The API runs locally and answers `GET /healthz`.
- Settings come from environment variables, with safe defaults.
- The code has empty layers with enforced boundaries: domain, ports, services, adapters, http.
- Formatting, linting, layer contracts, strict type checks, and tests all pass with one command.
- A production image builds, runs as a non-root user, and refuses to start with unsafe settings.
- CI runs every check and smoke-tests the image on each push and pull request.

## Scope

**In scope:** project files, dependencies, settings, logging, health probe, layer packages, test setup, tooling, Docker image, CI workflow, backend docs.

**Out of scope (built with features later):**

- API endpoints, serializers, and views.
- Domain models and business rules.
- Ports, provider adapters, and the composition root (`routing/bootstrap.py`).
- The API error format and its exception handler.
- Request-ID and request-logging middleware.
- A database. The service is stateless.

What the tool settings do:

- **Ruff:** 120-column lines, single quotes, LF. The rule set catches bugs, naive datetimes, `print`, and security smells.
- **mypy:** strict mode on all code, tests included. The Django and DRF plugins understand settings and views.
- **pytest:** uses the native `[tool.pytest]` table (pytest 9). Unknown markers and config keys are errors. Warnings are errors. Tests marked `live` are skipped unless you ask for them.
- **import-linter:** four contracts that keep dependencies pointing inward. They are explained in `CONVENTIONS.md` (step 11).
- **poe tasks:** short names for every command. `dev` and `test:live` load `.env`. Nothing else reads it.

Every value that changes between environments is read through these helpers. A malformed value stops the process at startup, not on the first request that needs it.

**`backend/config/env.py`**

```python
"""Typed readers for environment variables.

Settings read the environment only through these helpers. Every variable is
parsed in one place, an empty value counts as unset, and a malformed value stops
the process at startup instead of failing the first request that needs it.
"""

import os

from django.core.exceptions import ImproperlyConfigured

_TRUE = frozenset({'1', 'true', 'yes', 'on'})
_FALSE = frozenset({'0', 'false', 'no', 'off'})


def _read(name: str) -> str | None:
    value = os.environ.get(name, '').strip()
    return value or None


def env_str(name: str, default: str) -> str:
    return _read(name) or default


def env_bool(name: str, default: bool) -> bool:
    value = _read(name)
    if value is None:
        return default
    if value.lower() in _TRUE:
        return True
    if value.lower() in _FALSE:
        return False
    raise ImproperlyConfigured(f'{name} must be true or false, got {value!r}')


def env_int(name: str, default: int) -> int:
    value = _read(name)
    if value is None:
        return default
    try:
        return int(value)
    except ValueError:
        raise ImproperlyConfigured(f'{name} must be an integer, got {value!r}') from None


def env_list(name: str, default: list[str]) -> list[str]:
    """Reads a comma-separated list, dropping blank items."""
    value = _read(name)
    if value is None:
        return list(default)
    return [item.strip() for item in value.split(',') if item.strip()]


def env_choice(name: str, default: str, choices: frozenset[str]) -> str:
    value = env_str(name, default)
    if value not in choices:
        raise ImproperlyConfigured(f'{name} must be one of {sorted(choices)}, got {value!r}')
    return value
```

Settings decisions, in short:

- `DEBUG` defaults to **off**. Local development turns it on through `.env`.
- The fallback secret key has Django's `django-insecure-` prefix. `check --deploy` rejects it, so production cannot start with it.
- No database, sessions, admin, or auth apps. The API is stateless and public.
- DRF speaks JSON only. There is no authentication.
- Transport security (HTTPS redirect, HSTS) is on whenever `DEBUG` is off.
- Two deploy-check warnings are silenced on purpose, with the reason written next to each.

    'corsheaders',

    'corsheaders.middleware.CorsMiddleware',

    'django.middleware.clickjacking.XFrameOptionsMiddleware',

# feature needs to persist something.

LANGUAGE_CODE = 'en-us'
TIME_ZONE = 'UTC'
USE_TZ = True

# --- HTTP API --------------------------------------------------------------------

REST_FRAMEWORK = {

    'DEFAULT_PARSER_CLASSES': ['rest_framework.parsers.JSONParser'],

CORS_ALLOWED_ORIGINS = env_list('CORS_ALLOWED_ORIGINS', default=[])

# --- Transport security ----------------------------------------------------------------

SECURE_SSL_REDIRECT = env_bool('DJANGO_SECURE_SSL_REDIRECT', default=not DEBUG)

    # Submitting a domain to the HSTS preload list is the domain owner's call.
    'security.W021',

LOG_FORMAT = env_choice('LOG_FORMAT', default='text' if DEBUG else 'json', choices=frozenset({'json', 'text'}))

LOGGING = {

    'disable_existing_loggers': False,

HERE_API_KEY = env_str('HERE_API_KEY', default='')

The health probe runs first in the middleware stack. Platform health checkers call it over plain HTTP, with an internal `Host` header. So it must skip host validation and the HTTPS redirect.

**`backend/config/health.py`**

```python
"""Liveness probe, answered before the rest of the middleware stack.

`GET /healthz` returns 200 while the process can serve requests. It sits first
in `MIDDLEWARE` on purpose: platform health checkers call it over plain HTTP
with an internal Host header, so it must skip host validation and the HTTPS
redirect, and frequent polling must not flood the request logs.
"""

from collections.abc import Callable

from django.http import HttpRequest, HttpResponse, JsonResponse

HEALTH_CHECK_PATH = '/healthz'


class HealthCheckMiddleware:
    def __init__(self, get_response: Callable[[HttpRequest], HttpResponse]) -> None:
        self.get_response = get_response

    def __call__(self, request: HttpRequest) -> HttpResponse:
        if request.path == HEALTH_CHECK_PATH and request.method in {'GET', 'HEAD'}:
            return JsonResponse({'status': 'ok'})
        return self.get_response(request)
```

**`backend/config/json_logging.py`**

```python
"""One JSON object per log line.

Hosting platforms index these fields without a parser. Anything a call site
passes through `extra=` becomes a top-level field, so context is added as
`logger.info('route planned', extra={'routes': 3})`, never by formatting it into
the message.
"""

import json
import logging
from datetime import UTC, datetime
from typing import override

# Attributes every LogRecord carries. Anything else on a record came from `extra=`.
_RECORD_ATTRIBUTES = frozenset(logging.makeLogRecord({}).__dict__) | {'message', 'asctime'}


class JsonFormatter(logging.Formatter):
    @override
    def format(self, record: logging.LogRecord) -> str:
        entry: dict[str, object] = {
            'timestamp': datetime.fromtimestamp(record.created, tz=UTC).isoformat(timespec='milliseconds'),
            'level': record.levelname.lower(),
            'logger': record.name,
            'message': record.getMessage(),
        }
        entry.update({key: value for key, value in record.__dict__.items() if key not in _RECORD_ATTRIBUTES})
        if record.exc_info:
            entry['exception'] = self.formatException(record.exc_info)
        return json.dumps(entry, default=str)
```

### 8. Production image

Two stages:

1. **build:** uv installs the locked runtime dependencies into `/opt/venv`. Dev tools are left out.
2. **runtime:** a clean Python image gets the virtualenv and the source. It runs as an unprivileged user.

On start, the container runs Django's deployment checks. If the secret key, hosts, or security settings are unsafe, it exits before serving. Then gunicorn takes over as PID 1.

**`backend/Dockerfile`**

```dockerfile
# syntax=docker/dockerfile:1

# --- Build: resolve the locked runtime dependencies into a virtualenv ---------------
FROM python:3.14.8-slim AS build

COPY --from=ghcr.io/astral-sh/uv:0.13.1 /uv /usr/local/bin/uv

ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy \
    UV_PYTHON_DOWNLOADS=never \
    UV_PROJECT_ENVIRONMENT=/opt/venv

WORKDIR /app
COPY pyproject.toml uv.lock .python-version ./
RUN --mount=type=cache,target=/root/.cache/uv uv sync --locked --no-dev

# --- Runtime: the virtualenv plus the source, run as an unprivileged user ------------------
FROM python:3.14.8-slim AS runtime

ENV PATH="/opt/venv/bin:$PATH" \
    PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

RUN groupadd --system app && useradd --system --gid app --no-create-home app

WORKDIR /app
COPY --from=build /opt/venv /opt/venv
COPY . .

USER app
EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD ["python", "-c", "import os, urllib.request; urllib.request.urlopen(f\"http://127.0.0.1:{os.environ.get('PORT', '8000')}/healthz\", timeout=2)"]

# Refuse to start with unsafe production settings, then hand PID 1 to gunicorn.
CMD ["sh", "-c", "python manage.py check --deploy --fail-level WARNING && exec gunicorn config.wsgi"]
```

**`backend/CONVENTIONS.md`**

````markdown
# Backend conventions

Rules for code in `backend/`. Tools enforce most of them. Reviews enforce the rest.

## Architecture: ports and adapters

Dependencies point inward. Business rules never know which provider, framework, or transport is in use.

```text
HTTP request
    │
    ▼
routing.http ──────────► routing.bootstrap ──────────► routing.adapters
 (DRF views,              (composition root:             (HERE, weather API,
  serializers)             builds adapters,               caches)
    │                      injects them)                      │
    ▼                            │                            │ implements
routing.services ◄───────────────┘                            ▼
 (use cases) ──────────────────────────────────────────► routing.ports
                                                          (Protocols)
                                                              │
                                                              ▼
                                                        routing.domain
                                                         (pure rules)
```

| Package | Holds | May import | Must not import |
|---|---|---|---|
| `routing.domain` | Business rules and value objects | Standard library | Anything else |
| `routing.ports` | `typing.Protocol` interfaces and their typed errors | `domain` | `services`, `adapters`, `http`, Django, httpx |
| `routing.services` | Use cases | `domain`, `ports` | `adapters`, `http`, Django, httpx |
| `routing.adapters` | Port implementations for real providers | `domain`, `ports`, httpx, provider libraries | `services`, `http` |
| `routing.http` | DRF views, serializers, routes, error translation | `services`, `domain`, `bootstrap`, DRF | `adapters` directly |
| `routing.bootstrap` | Composition root | Everything in `routing`, Django settings | — |
| `config` | Django project and shared infrastructure | Django | `routing` code (dotted-path strings in settings and URLs are fine) |

`uv run poe lint` runs import-linter. It enforces the first five rows. A broken contract fails CI.

**Composition root.** `routing/bootstrap.py` is created with the first service. It is the only module that reads provider settings and constructs adapters. It exposes small provider functions, such as `get_plan_trip_service()`. Views call them. Tests replace them to inject fakes.

**Cross-cutting behaviour is a decorator, not a layer.** For example, caching wraps a port: `CachedForecast` implements the same Protocol as the real adapter and holds it. Services never know caching exists. Turning it off is a one-line change in the composition root.

## Naming

| Thing | Style | Example |
|---|---|---|
| Package, module | `snake_case` | `routing/adapters/here_router.py` |
| Class | `PascalCase` | `HereRouter`, `RoutePlan` |
| Function, method, variable | `snake_case` | `plan_trip`, `arrival_time` |
| Constant | `UPPER_SNAKE_CASE` | `MAX_CHECKPOINTS` |
| Private name | Leading underscore | `_parse_route` |
| Port | The role it plays, no `I` prefix | `RouteProvider` |
| Adapter module | `<vendor>_<capability>.py` | `open_meteo_forecast.py` → `OpenMeteoForecast` |
| Decorator adapter | `<concern>_<port>.py` | `cached_forecast.py` → `CachedForecast` |
| Test fake | `Fake<Port>` in `tests/<layer>/fakes.py` | `FakeRouteProvider` |
| Test | `test_<expected_behaviour>` | `test_wind_at_55_mph_is_no_travel` |

## Code

- Annotate every function. mypy runs in strict mode on all code, tests included.
- Value objects are `@dataclass(frozen=True, slots=True)`. Closed sets are `enum.StrEnum`. Outside capabilities are `typing.Protocol`.
- `Any` stays at untrusted boundaries: provider JSON and request bodies. Narrow it to a typed value right away. Never pass raw provider dictionaries inward.
- Datetimes are timezone-aware. Ruff's `DTZ` rules reject naive ones.
- A number with a unit carries the unit in its name: `distance_miles`, `wind_mph`, `duration_seconds`.
- Domain functions are pure. Pass the current time in; never read the clock in the domain.
- Keep modules small and single-purpose. Split a module when it needs a table of contents.

## Errors

- Each layer that can fail defines typed exceptions in its own `errors.py`.
- Adapters catch provider and transport failures and raise the port's errors. httpx exceptions never leave an adapter.
- The HTTP layer turns errors into responses in one place: a DRF exception handler. Views do not catch and format errors themselves.
- Error messages state the rule that failed. They never contain secrets or raw provider payloads.

## Configuration

- Only `config/settings.py` reads environment variables, always through `config/env.py`.
- Defaults are safe for local development and tests. Production values come from the environment.
- Every variable is listed in `.env.example`, with a comment.
- Services receive settings as constructor arguments from the composition root. `domain` and `services` never import `django.conf.settings`.

## HTTP API

- Every endpoint lives under `/api/v1/`. JSON in, JSON out.
- A view parses input with a serializer, calls one service, and returns the serialized result. No business rules in views.
- `/healthz` is the liveness probe. It is middleware, not a route.

## Logging

- Declare `logger = logging.getLogger(__name__)` at the top of the module.
- Keep the message constant. Put context in `extra`: `logger.info('route planned', extra={'routes': 3})`.
- Never log secrets, API keys, or full provider payloads.
- Production logs one JSON object per line (`LOG_FORMAT=json`). Local development uses `text`.

## Tests

- pytest. Tests live in `tests/` and mirror the package: `tests/domain/`, `tests/services/`, `tests/adapters/`, `tests/http/`.
- Prefer small hand-written fakes that implement a port over mocks.
- Default tests never touch the network. Adapter tests replay recorded JSON through `httpx.MockTransport`.
- Tests that call real provider APIs carry `@pytest.mark.live`. They are skipped by default. Run them with `uv run poe test:live`.
- Use Hypothesis for rules that must hold for every input, such as thresholds and orderings.
- Structure each test as arrange, act, assert, separated by blank lines.

## Comments and docstrings

- Every package has a docstring that states its rule.
- Docstrings and comments explain why: the decision, the constraint, the trade-off. The code already says what.
- No commented-out code. Delete it; git keeps the history.

## Formatting

Ruff formats everything: 4-space indents, single quotes, 120-column lines, LF endings. Do not format by hand. Run `uv run poe format`.
````

### 12. CI workflow and Dependabot
