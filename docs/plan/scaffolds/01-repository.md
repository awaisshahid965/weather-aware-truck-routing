# Plan 01: Repository foundation

## Goal

Set up the repository root. Every later change in `backend/` and `frontend/` relies on it.

When this plan is done:

- Line endings, encoding, and indentation are the same on every machine.
- Git hooks run on every commit. They check staged files and the commit message.
- Dependabot proposes dependency and GitHub Actions updates every week.
- The root README, contributing guide, license, and PR template exist.

## Scope

**In scope:** root configuration files, git hooks, commit rules, editor settings, Dependabot, contributor docs.

**Out of scope:** the Django app, the Next.js app, and CI workflows. Each app sets up its own files, hook rules, and CI workflow.

## Steps

### 1. Create a branch

```bash
git switch main
git switch -c chore/repository-setup
```

### 2. Normalize text files

Git stores every text file with LF endings, on every OS. Lockfiles are marked as generated, so GitHub collapses them in pull request diffs.

Replace the contents of `.gitattributes`:

**`.gitattributes`**

```gitattributes
# Store text files with LF line endings on every platform.
* text=auto eol=lf

# Generated lockfiles: collapsed in GitHub diffs.
package-lock.json linguist-generated=true
uv.lock linguist-generated=true
```

Then renormalize any files that are already committed:

```bash
git add --renormalize .
```

### 3. Editor defaults

EditorConfig gives every editor the same basics. The formatters (Prettier, Ruff) enforce the same values.

**`.editorconfig`**

```ini
root = true

insert_final_newline = true
trim_trailing_whitespace = true

[*.{json,yml,yaml}]

[*.md]
```

### 6. Git hooks

**How it works:**

1. `npm install` runs the `prepare` script. Husky points git at `.husky/`.
2. On `git commit`, the `pre-commit` hook runs lint-staged.
3. lint-staged finds the `.lintstagedrc.json` closest to each staged file. Commands run in that config's folder, with that folder's tools.
4. The root config below covers root files. Each app adds its own config when it is scaffolded (`backend/.lintstagedrc.json`, `frontend/.lintstagedrc.json`).
5. A staged file that matches no pattern in its config (for example a Markdown file) is skipped.
6. The `commit-msg` hook checks the first line of the commit message.

lint-staged refuses to run with no config at all, so the root config must exist before the first commit with hooks.

**`.lintstagedrc.json`**

```json
{
  "*.{json,yml,yaml}": "prettier --write"
}
```

**`.husky/pre-commit`**

```sh
npm run lint-staged
```

**`.husky/commit-msg`**

```sh
# Enforces a Conventional Commits subject line: type(optional-scope): summary
subject=$(head -n 1 "$1")

case "$subject" in
    "Merge "* | "Revert "* | "fixup! "* | "squash! "* | "amend! "*) exit 0 ;;
esac

if ! printf '%s\n' "$subject" | grep -Eq '^(feat|fix|refactor|perf|test|docs|build|ci|chore|revert)(\([a-z0-9-]+\))?!?: .+$'; then
    echo ""
    echo "Invalid commit message: $subject"
    echo ""
    echo "Expected: <type>(<optional-scope>): <summary>"
    echo "Types: feat, fix, refactor, perf, test, docs, build, ci, chore, revert"
    echo "Examples:"
    echo "  feat(backend): add health endpoint"
    echo "  fix(frontend): keep map attribution visible"
    echo "  chore: update dependencies"
    echo ""
    exit 1
fi
```

Install the tools and activate the hooks. Run plain `npm install` with no package names: only that form runs `prepare`.

```bash
npm install
```

This creates `package-lock.json` and `node_modules/`. It also sets `git config core.hooksPath` to `.husky/_`.

### 7. Dependabot

Dependabot opens weekly update PRs. Its commit messages follow the commit rule, for example `build(deps): bump husky from 9.1.7 to 9.1.8`.

Only root ecosystems are listed here. Each app appends its own entries under `updates:` when it is scaffolded.

**`.github/dependabot.yml`**

```yaml
version: 2
updates:
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
    commit-message:
      prefix: build
      include: scope
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
    commit-message:
      prefix: ci
      include: scope
```

### 11. Contributing guide

**`CONTRIBUTING.md`**

````markdown
# Contributing

## Setup

Run `npm install` once in the repository root, with Node.js 24.22.0. It installs the git hooks. Each app's README covers the rest of its setup.

## Branches

- `main` is always releasable. Never commit to it directly.
- Branch from `main`. Name the branch `<type>/<short-topic>`, for example `feat/route-checkpoints` or `fix/heatmap-slider`.
- Keep one concern per branch. Open a pull request into `main`. Delete the branch after it merges.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/). The `commit-msg` hook rejects anything else.

```text
<type>(<optional-scope>): <summary>
```

| Type | Use it for |
|---|---|
| `feat` | A new user-facing capability |
| `fix` | A bug fix |
| `refactor` | A code change that does not change behaviour |
| `perf` | A performance improvement |
| `test` | Adding or fixing tests only |
| `docs` | Documentation only |
| `build` | Dependencies, build tooling, Dockerfiles |
| `ci` | CI workflows |
| `chore` | Anything else (repository housekeeping) |
| `revert` | Reverting an earlier commit |

- Scope: `backend` or `frontend`. Leave it out for changes across the whole repository.
- Summary: imperative mood, lowercase, no trailing period. Example: `feat(backend): add route checkpoint sampling`.
- Add `!` after the type or scope for a breaking change: `feat(backend)!: rename route plan fields`.

## Git hooks

| Hook | What it runs |
|---|---|
| `pre-commit` | lint-staged, on staged files only. Root JSON and YAML: Prettier. App files: the rules in that app's `.lintstagedrc.json`. |
| `commit-msg` | The commit message rule above. |

Do not skip hooks with `--no-verify`. If a hook is wrong, fix the hook.

## Before opening a pull request

Run the full check for each app you changed. CI runs the same commands.

| App | Command |
|---|---|
| Backend | `cd backend && uv run poe check` |
| Frontend | `cd frontend && npm run check` |

Fill in the pull request template: what changed, why, and how you tested it.

## Dependencies

- Versions are pinned exactly. Lockfiles are committed: `package-lock.json`, `backend/uv.lock`.
- Dependabot opens update PRs every week. Review the changelog, run the checks, then merge.
- Upgrade on purpose, in its own pull request, with a `build(deps): ...` commit.
````
